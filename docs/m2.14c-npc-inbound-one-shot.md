## Offline-gated implementation

`src/admin/discord-npc-e2e-inbound.ts` is a separate local operator CLI.
It reuses **only the previously tested one-shot transport/message filter** from
`discord-pilot-gateway.ts`, with the new target IDs. It does **not** reuse
the consumed Step 14 world, static DB verifier or old thread. The runner accepts
exactly one fresh direct mention of the DEV bot by the single mapped human,
inside this one **Public Thread** under the new private parent:

```text
@Living World [Sentinel] Report readiness.
```

Here `@Living World` must be an actual Discord app mention selected from the
mention picker. The stored raw message must equal
`<@1566909036899868712> [Sentinel] Report readiness.` (or Discord's
equivalent `<@!1566909036899868712>` form). No additional text, replies,
other channels/threads, other players, bots or webhooks are permitted.

The default mode is `--preflight` and opens **no Discord connection**.
It checks the dedicated local PG17 database, route, player mapping, co-located
trusted NPC presence, activation policy audit, and no prior interaction/delivery.
The event is additionally fenced to be newer than the Gateway session arm time;
post-event read-only audit checks source event creation time after presence,
route and policy activation, and exactly one inert `received` interaction with
no NPC response or delivery. A failure stops the pilot; never auto-retry an
uncertain/consumed session.

Safety: the command requires `DISCORD_ENABLED=false`,
`DISCORD_OUTBOUND_ENABLED=false`, `LLM_PROVIDER=disabled`, correct
`LW_DEV_BOT_USER_ID` and private `DISCORD_TOKEN`. It has **no outbound
send**, provider call or model generation and does not start normal
`src/runtime.ts`. It doesn't modify the Step 8/Step 14 worlds.

## Owner-local operations — not authorized to run live yet

From a clean, freshly fast-forwarded `main` **after** the PR is separately
approved and merged, and only against the already-verified owner's
isolated local PostgreSQL:

Read-only, non-network preflight:

```bash
node --env-file=.env.gateway-dev.local --env-file=.env.gateway-pilot.local --env-file=.env.gateway-npc-e2e.local --import tsx src/admin/discord-npc-e2e-inbound.ts --preflight
```

Expect `{"event":"npc_e2e_inbound_preflight_valid"}`. If the DB/world
is already consumed, the preflight fails safely. Do not re-run
`--activate` or provision another fixture as a workaround.

**LIVE CONNECTION — DO NOT EXECUTE WITHOUT A NEW OWNER APPROVAL:**

```bash
node --env-file=.env.gateway-dev.local --env-file=.env.gateway-pilot.local --env-file=.env.gateway-npc-e2e.local --import tsx src/admin/discord-npc-e2e-inbound.ts --connect --confirm-world lw-dev-npc-e2e-001 --confirm-world-id e551f23e-2393-4726-af97-828ef3587625 --confirm-context bd921a22-7abc-4c08-ae55-bd7050d9c4f7 --confirm-guild 1566911648701223053 --confirm-parent 1568349822505717830 --confirm-thread 1568350458026786886 --confirm-database living_world_gateway_dev --inbound-only --one-message
```

It will log legacy tested transport event labels
`pilot_gateway_ready`, `pilot_gateway_received`,
`pilot_gateway_audit_pass`, `pilot_gateway_stopped`, then the new
`npc_e2e_inbound_complete`. These legacy labels do not mean the consumed
Step 14 scope was reused.

If the runner terminates without a successful audit, inspect database state
read-only **before attempting any action**; the single accepted interaction
may have committed before a later transport timeout/error.
Once successfully consumed, `ready_for_inbound` intentionally changes to
`already_used`. This is expected, and automatic replay must be refused.
