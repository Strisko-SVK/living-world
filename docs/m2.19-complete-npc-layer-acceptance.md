## Permanent inference service (prepared artifacts; **not deployed**)

Artifacts:

On the Hetzner server, operator must first inspect the running process, available memory and actual llama.cpp binary. **Stop the existing foreground/tmux llama process gracefully before enabling this service** to avoid two simultaneous models or a port collision.

From Mac repository root (using existing owner SSH identity; review the files before installing):

```bash
scp -i ~/.ssh/living_world_hetzner \
  infra/inference/start-llama.sh \
  infra/inference/living-world-llama.service \
  infra/inference/llama.env.example \
  livingworld@2.31.49.192:/tmp/
ssh -i ~/.ssh/living_world_hetzner livingworld@2.31.49.192
```

On the server (only after checking `~/raon-probe/llama.cpp/build/bin/llama-server` and reviewing model settings):

```bash
sudo install -d -m 0755 /etc/living-world
sudo install -m 0755 /tmp/start-llama.sh /usr/local/bin/living-world-llama-start
sudo install -m 0600 /tmp/llama.env.example /etc/living-world/llama.env
sudo install -m 0644 /tmp/living-world-llama.service /etc/systemd/system/living-world-llama.service
sudo systemctl daemon-reload
sudo systemctl enable --now living-world-llama.service
systemctl status living-world-llama.service --no-pager
journalctl -u living-world-llama.service -n 40 --no-pager
curl -fsS --max-time 10 http://127.0.0.1:8000/health
curl -fsS --max-time 10 http://127.0.0.1:8000/v1/models
```

The service starts as `livingworld`, binds only to loopback 8000, restarts on failure and starts after reboot. Model switching: `sudoedit /etc/living-world/llama.env`, verify model is cached/available, then `sudo systemctl restart living-world-llama.service`; verify `/v1/models` alias and Mac tunnel before starting Gateway. For rollback: `sudo systemctl disable --now living-world-llama.service`; existing data and models remain untouched. No service should be reported as live until actual operator validation.

### Continuous 30-turn script — reply naturally, do not copy expected NPC lines

Use a single authorized NPC scene. Each numbered item is one **player** turn. Record actual response, trace ID, latency, completion reason and pass/fail. This script is a *future acceptance test*, not proof of implemented memory/task/state functionality.

1. Hello. Who are you?
2. What is your job here?
3. I need forks for my miners to dig tunnels.
4. Why do you think that's odd?
5. Actually, I need twenty forks for their dinner.
6. Can you confirm the stock before promising anything?
7. What alternatives could you suggest if no stock record exists?
8. Tell me a short joke about this confusion.
9. Change of topic: have you seen any unusual cargo?
10. Who told you that? What do you actually know?
11. I heard that the cargo ship was destroyed.
12. Does that prove the ship was destroyed?
13. I retract that claim: it was only a rumor.
14. Back to the forks: how many did I ask for?
15. Correction: make that sixteen, not twenty.
16. Who is the captain of a ship you have never heard of?
17. Explain carefully why you cannot know without evidence.
18. Thank you for not inventing an answer.
19. I need help arranging a legitimate supply request.
20. What do you need to clarify before accepting it?
21. Ask the NPC for the status of that request, if accepted.
22. Ask whether a DM-defined task outcome has been received.
23. Speak informal Slovak: "Ahoj, co nove?"
24. Slovak without diacritics: "Kolko tych vidliciek teda potrebujem?"
25. Mix languages: "Dobre, but please keep the quantity accurate."
26. Ask a more emotional question requiring empathy.
27. Ask for a detailed explanation, not a two-sentence answer.
28. End the conversation and restart the Gateway safely.
29. Return to the same authorized scene: "Remember the corrected number?"
30. Ask for the authorized task report and what remains unknown.

**Independent multi-player/multi-NPC follow-up:** In an authorized shared scene, Player A makes a private claim to Marcus; Player B talks to Sentinel, then Player A addresses Nemeia. Check that private claims do not leak and each NPC has different style. Repeat with different relationships to the same NPC and a private thread with a non-member denied. Record duplicate-event handling, reboot continuation and provider outage separately.
