# M2.15H — host-fenced fake response and delivery lifecycle

## Outcome under test

A **new synthetic Discord source event**, already validated in the
rollback-only `npc-gateway-ci-*` PostgreSQL fixture, may pass a short-lived
host scene-speech decision and exercise the existing response orchestrator,
response store, durable delivery outbox and fake Discord transport.
One fake ACK is persisted **inside a rollback-only test transaction**.
There is no live Discord message or paid model request.

Unlike M2.15G's in-memory `fake_ack`, this exercise reaches the
real PostgreSQL generation claim, prompt context, response persistence,
outbox claim/preflight, fake transport acknowledgment and duplicate fence.

## Implementation boundary

- `readVerifiedOfflineSpeechPhaseSnapshot` extends the existing
  CI-only PostgreSQL scene policy projection with explicit lifecycle states:
  `received`, `prepared`, `dispatched`, `responded` and `sending`.
- Every phase verifies the original immutable event, active mapped player,
  unchanged source route and epoch, NPC alias and location, the same
  non-revoked presence, active bounded host decision, and state revision.
- Later phases additionally require the exact local-presence binding,
  response claim/generation lifecycle, and for `sending` exactly one
  first-flight outbox lease with no prior ACK or retry.
- The fake provider checks the `dispatched` phase immediately before its
  synthetic generation. The fake transport checks the `sending` phase
  immediately before acknowledging. A changed route or revoked/expired
  policy blocks fake continuation.
- The already existing M2.15D and M2.15G strict checks remain in place.
  A candidate always preserves `canGenerate=false` and `canSend=false`
  for **real** services.
- Tests include first delivery ACK, one-shot duplicate denial and a
  PostgreSQL savepoint rollback proving no persistent test residue.

## Safety boundaries

No new migration; no owner DEV database or fixture mutation; no
Discord Gateway connection, Discord send, webhook execution or real LLM call.
The provider is `fakeProvider()` and the transport is
`fakeDeliveryTransport()`. All DB tests run against disposable
`living_world_ci`, all synthetic transactions roll back.

The test is **not** real action-time authorization for production. Real
provider and outbound boundaries still need to enforce a trusted
one-shot owner opt-in, exact route/actor/world, current policy and presence
under the production transaction/HTTP execution pattern. An original
previously consumed Sentinel event cannot be retroactively authorized.

## Approval gates

Independent owner consent required before PR squash merge; separate
owner approval before any persistent DEV database modification, runtime
connection, real Discord send, real LLM API call or deployment.
