# M2.13B — Player summon availability, offline foundation

**Status:** Draft, evidence-only. Not connected to live Discord or the NPC
response runtime. No DM override or NPC movement in this slice.

## Owner rule

A player may call an NPC without assigning the NPC a Discord membership.
The call is a narrative request, not automatic presence or permission to
speak. NPC location, ongoing activity and scene conflicts matter because
NPCs have lives outside the current player scene.

DMs can later request a *private read-only* view of location and activity,
then separately decide whether to respect the NPC's situation or make an
explicit, auditable narrative override. Player text must not grant DM
authority. A DM query must never mutate state or leak hidden information.

## Implemented contracts

- `src/communication/summon-availability.ts` evaluates trusted facts.
  Its result is `candidate`, `delayed`, `not_available` or `unknown`.
- Every result has `mayGrantPresence: false` and `maySendSpeech: false`.
  Even a `candidate` needs a later state transition and transactional
  checks before local speech can be considered.
- Facts include lifecycle, scene status, exact location certainty,
  activity, perception, competing scene and NPC state version.
- Missing, invalid, untrusted or ambiguous facts fail closed; active
  scene conflicts, dead/dormant NPCs and known different locations
  cannot be bypassed by simply calling an alias.
- `src/communication/summon-facts.repository.ts` reads the existing
  world-scoped NPC and scene state without modification. The current
  schema stores activity in free-text summaries rather than verified
  structured evidence; the reader therefore reports activity,
  perception and competing scenes as `unknown`. It never invents
  facts from story text or an LLM.

## Validation

Unit tests cover all outcomes, uncertain location, busy or absent NPCs,
scene conflicts, asserted DM/force flags and invalid evidence.

Three real PostgreSQL tests verify that co-location alone still yields
`unknown`, an NPC at a different location is not teleported and
foreign world/scene IDs cannot expose the state snapshot. The test
fixtures use disposable CI worlds only.

**Verified:** commit `11b34401`, CI run `42232050571`:
660 unit PASS, 330 PostgreSQL PASS, isolated Gateway DEV PASS.

## Not yet implemented

Structured authoritative activity/perception evidence, stale-snapshot
fencing and concurrent scene scheduling need additional design and
tests. A `candidate` is *never* automatic speech or arrival. Private
DM observation needs world-scoped permissions and a non-public reply
channel before it can be exposed. An explicit DM force-arrival must
be a separate logged action, not a caller flag in player intake.

No merge, deployment, real Discord requests, owner DEV database writes,
paid LLM calls or production response-worker changes are authorized.
