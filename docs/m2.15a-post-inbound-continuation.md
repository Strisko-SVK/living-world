# M2.15A — Offline continuation after persisted NPC inbound

**Status:** Draft-only. No live activity authorized.

## Why this slice exists

The sixth Sentinel one-shot accepted one Discord message and audited its
database write. Readiness is now `already_used`: one inert interaction,
zero outbound deliveries. This is the expected consumed test fixture.

The existing M2.13B handshake starts with intake. If we try to ingest the
same Discord event again, intake correctly returns `duplicate`. We must not
reset or replay the successful owner DEV fixture to generate a response.

This milestone adds a separate, test-only continuation from a persisted event.
It never runs in the production app, Gateway or outbound operator CLI.

## Safety contract

1. Validate the original world, scene, NPC, interaction and Discord event.
   The requested identifiers are lookup keys, not authorization evidence.
2. Require exactly one persisted `received` event with unchanged source
   binding, player speaker, scene mapping and `unknown` communication mode.
3. Revalidate current player mapping and scene route in the trusted database.
   Deny if either was revoked, disabled or replaced.
4. Read pre-existing NPC presence from trusted data only. Use the existing
   `prepareLocalInteraction` transaction to check NPC location/version,
   source timing, scene policy and revocation before local preparation.
5. Continue only on `prepared` with the existing disposable-world harness.
   It uses fake LLM output and in-memory transport with a fake ACK.
6. Require `NODE_ENV=test`, with Discord and paid provider disabled.
   Never retry automatically, including after an uncertain outcome.
7. Emit only fixed-category diagnostic outcomes. Never log messages, IDs,
   credentials, database errors or provider payloads.

## Tests and verification

- Unit tests: strict scope, binding, duplicate, mapping, route and presence.
- Unit tests: denied preparation, uncertain result and diagnostic privacy.
- Real PostgreSQL: accepted intake once, followed by fake generation and ACK.
- Real PostgreSQL: revoked player, original route or presence prevents reply.
- Mandatory CI: quality, PostgreSQL 17, isolated DEV, security and CodeQL.

No migration, production runtime wiring or owner DEV database changes.

## Still out of scope

This does not turn the consumed Sentinel interaction into a live NPC reply.
We must separately design a read-only eligibility preview, narrative response
review and explicitly approved single-message outbound operation.

Do not reconnect the Gateway, re-arm or reset the fixture, change ACL,
grant presence, make paid calls, deploy or merge under this milestone.
