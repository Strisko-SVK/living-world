# M2.15G — PostgreSQL-backed fake-only scene speech rehearsal

## Goal

Connect the **existing** M2.15E trusted host scene-speech policy table
to the **existing** M2.15D fake-only rehearsal coordinator. Previously
`readTrustedSnapshot` was only a mocked injected function, so a real
PostgreSQL-backed positive path had not been demonstrated.

This milestone provides evidence that a **fresh synthetic** Discord
interaction, created **after** a bounded host decision, is eligible for
an **in-memory fake acknowledgement**. It does **not** send any Discord
message, invoke OpenAI, create a response delivery, or enable a new
runtime feature.

## Implementation

- `src/offline/npc-pg-speech-snapshot.ts` composes the original
  PostgreSQL event, mapped sender, unchanged Discord route and revision,
  world/context/NPC, local presence, normalized NPC alias, stored host
  scene-speech policy, and current NPC state inside one transaction.
- All facts originate from the database; only UUID scope keys are
  accepted from the caller. A claimed DM role, operator flag, activity
  or policy is rejected as an unknown field.
- Restricted to Vitest `NODE_ENV=test`, disabled Discord and outbound,
  disabled LLM, authenticated `living_world_ci` database role, and
  synthetic `npc-gateway-ci-*` worlds. The owner's persistent
  `living_world_gateway_dev` is explicitly refused.
- Reuses `assessSceneContact`, `readTrustedHostScenePolicy` and
  `assessOfflineSpeechReadiness`. If any evidence is stale, missing,
  revoked, a replay, or sourced from a mismatched world, returns
  `null` and cannot reach the fake collaborator.
- `src/db/discord-npc-e2e-inbound.db.test.ts` extends the existing
  **rollback-only** PostgreSQL 17 fixture to prove that the real
  snapshot drives `createOfflineSpeechRehearsal` to one in-memory
  fake string: _Sentinel-001: Acknowledged. Standing by._
  The test exercises wrong scope, spoofed DM claim, route revision and
  host-policy revocation. No real send/LLM is imported.
- Unit regressions cover production/runtime flags, malformed scope and
  fail-closed DB exceptions.

## Existing boundary maintained

The pure readiness result still has `canGenerate=false`,
`canSend=false`, `canGrantPresence=false`. A `fake_ack` is only a
local test result and is not proof of real delivery or a production
authorization. The fake phrase is test fixture text, **not** model output.

There is no new migration; owner's local migration 0018 is already
completed and preserved. This branch must not read/modify the owner's
DEV data, rearm or reuse the historical Sentinel message, enable
Discord Gateway, send a message, bill an LLM, merge or deploy without
a separate owner approval. The synthetic source event in CI is fresh,
not the consumed owner-local one.

### Still required for a real Discord reply

Trusted world-scoped DM membership and authorization; independently
verifiable activity/perception and conflicting-scene state (the host
decision here is an explicit short-lived attestation, not a simulation);
fresh inbound after authorization; and action-time transactional
revalidation of route, presence, policy and limits before **real**
generation/outbound. These require separate security review and owner
approval for any live pilot.
