2. Ensure the new Private Thread and DEV bot membership/ACL are configured.

   Gateway and ONE exact fixed-text reply to the next authenticated player

   `DISCORD_OUTBOUND_ENABLED=false`, `LLM_PROVIDER=disabled` remain required.

5. Execute fresh read-only `dev-first-reply-provision.ts --preview`,

   `--prepare` activates a 30-minute host policy; perform the session promptly.

## One local session, no ChatGPT roundtrip after the event

The new `src/admin/dev-first-reply-session.ts` entrypoint accepts only:

```text
--run --confirm-world lw-dev-first-reply-002
--confirm-guild <DEV_GUILD_ID>
--confirm-parent <NEW_PARENT_ID>
--confirm-thread <NEW_PRIVATE_THREAD_ID>
--confirm-database living_world_gateway_dev
--one-inbound --one-reply --no-retry
```

The entrypoint requires a real interactive terminal and an already provisioned
fixture. Before touching Discord, it verifies exact env, the three explicit
operator approval flags, an OS-owned 0600 local key (without printing it),
read-only database/gateway preflight, and a fresh not-consumed world.

When `pilot_gateway_ready` appears, the user sends exactly **one** literal
Discord bot mention in the new private thread:
`@Living World [Sentinel] Report readiness.` using Discord's actual user
mention, not plain text. Gateway has a 90-second timeout.

The runner waits for authenticated SDK intake + DB post-write audit, then
immediately reads the sole source snowflake **locally and read-only**, validates
it is younger than 120 seconds, and invokes the already reviewed,
separately-authorized **`runFirstReplySendCommand`** in the same process.
That send entrypoint still requires a source-bound typed confirmation in
the operator's local terminal **after** the event, performs two independent
authenticated Discord identity/route/Private Thread membership/ACL/source GET
fences, and creates one immutable DB consent/claim/outbox attempt before a
single fixed-text POST. It cannot send other text, mention any account, enable
LLM, route to another channel, or retry. The user should type the exact
`SEND <source-last-5> Acknowledged. Standing by.` prompt promptly.

If any precheck fails, there is **no send**. A claimed attempt, network
ambiguity, process crash or missing acknowledgement is **terminal**: never
replay or retry. Inspect the original private thread and sanitized DB audit
rather than risking a duplicate.
