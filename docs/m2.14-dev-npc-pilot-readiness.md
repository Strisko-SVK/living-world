## Read-only commands (after owner verifies Docker/database context)

On the intended local machine, from the repo root:

```bash
git status --short
git rev-parse HEAD
docker context show
docker context inspect
docker compose --env-file .env.gateway-dev.local -f compose.gateway-dev.yml ps
node --env-file=.env.gateway-dev.local --import tsx src/admin/gateway-dev-db.ts check
```

**Stop** if the Docker context targets a remote host, the isolated service is absent, or the DB identity fails. Never start/reset a service automatically as part of an audit.

After a new Discord route has been separately approved and its two local IDs saved, the existing M2.13A fixture preview can be used. It does **not** apply any fixture data:

```bash
node --env-file=.env.gateway-dev.local --env-file=.env.gateway-pilot.local --env-file=.env.gateway-npc-e2e.local --import tsx src/admin/discord-npc-e2e-fixture.ts --preview
```

The new M2.14A inspector performs a DB transaction with `SET TRANSACTION READ ONLY` as its first statement. It checks database/role/version, route isolation, migration-trigger presence, world/scene/NPC/player structure, policy and audit, exact mapped test player when locally provided, matching NPC presence, and consumed interaction/delivery counts:

```bash
node --env-file=.env.gateway-dev.local --env-file=.env.gateway-pilot.local --env-file=.env.gateway-npc-e2e.local --import tsx src/admin/discord-npc-e2e-readiness.ts --preview
```

Possible statuses:

| Status | Interpretation |
| --- | --- |
| `fixture_missing` | Fresh parent route is free, but synthetic world does not exist |
| `default_deny` | Existing world is inert: no player/presence/intake/audit |
| `migration_required` | Route is valid, but the 0017 route-revision trigger is missing |
| `setup_required` | Not all required player/presence/policy evidence is present; manual review required |
| `ready_for_inbound` | DB-side evidence is consistent; **does not** verify Discord ACL or authorize Gateway login |
| `already_used` | Pilot was consumed: never replay automatically |
| `blocked` | Route/world conflict or incompatible state; stop and investigate |

The inspector has **no** `--apply`, `--connect`, `--send` or `--execute` operation. These commands require an **existing** local database; they neither start Docker nor create a fixture. It reads the database, so it is not a zero-contact operation; it is nonmutating.
