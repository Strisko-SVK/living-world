# M2.15L — real DEV PostgreSQL read-only first-reply preview

## Purpose

The first owner-visible milestone is still one **real, fixed-text** NPC reply in
a new, private Discord DEV thread. M2.15K proved the one-shot contract only
with unit-test doubles. This milestone adds the first **actual
`living_world_gateway_dev` PostgreSQL reader** for the future pilot, with no
authorization to send.

Unlike M2.15G/J's `living_world_ci`-only speech snapshot, the operator
command here can assess a **fresh, separately provisioned DEV test world**,
but cannot prepare, generate, dispatch, log in to Discord or send anything.

## Entry point

`src/admin/npc-dev-first-reply-preview.ts`

Preview is the **only supported** command. `--execute`, `--send`,
`--apply`, `--reset` and extra arguments are explicitly rejected.
Required local environment (never commit credentials):

- Existing dedicated `.env.gateway-dev.local` with loopback-only PostgreSQL
  17 credentials, `DISCORD_ENABLED=false`,
  `DISCORD_OUTBOUND_ENABLED=false`, `LLM_PROVIDER=disabled`
- `LW_FIRST_REPLY_WORLD_KEY` — a brand-new
  `lw-dev-first-reply-...` world, **not** the used
  `lw-dev-npc-e2e-001` world
- `LW_FIRST_REPLY_GUILD_ID`, `LW_FIRST_REPLY_PARENT_ID` and
  `LW_FIRST_REPLY_THREAD_ID` — the exact fresh private DEV route, not the
  pristine/baseline or any consumed pilot route
- `LW_FIRST_REPLY_PLAYER_ID` — the intended mapped human Discord user

Future operator command, **only after separate fixture/DB-read approval**:

```bash
node --env-file=.env.gateway-dev.local --import tsx src/admin/npc-dev-first-reply-preview.ts --preview
```

No command is required on the owner's machine for the current PR.

## Database safety and evidence

The CLI validates a dedicated local loopback PostgreSQL URL and credentials
_before connecting_. On connection it opens a transaction, sends
`SET TRANSACTION READ ONLY` as the **first SQL statement**, sets an
eight-second statement timeout and verifies exact database
`living_world_gateway_dev`, role `lw_gateway_dev`, PostgreSQL 17 and
non-privileged DB role flags. Missing identity is blocked before any
NPC/world record is accessed.

It checks that the route revision and host policy DB guards are enabled,
that one fresh active test world/scene and exact route exist, and that:

- Only **one** original interaction exists in that new world, it is
  `received` and unprocessed, has a fresh Discord source ID and unchanged
  original mapping, and no prior outbox exists.
- Only one active player identity matches the configured Discord author,
  and its world-scoped character matches the stored speaker.
- The explicit bot trigger uniquely resolves the active NPC alias.
- Exactly one non-revoked local-presence record matches the same NPC/scene,
  and the source event was created after the route and presence evidence.
- An intact, time-bounded host-operator scene speech policy is non-revoked,
  issued by the trusted database role, and predates the original event.
  The existing contact and offline readiness evaluators must both pass.

Even a positive verdict reports only `fake_only_candidate`, with fixed
`canGenerate=false`, `canSend=false`, `wouldSend=false`,
`readOnly=true`. There is no HTTP, Discord SDK client, webhook, LLM,
response store, outbox writer, or persistent pilot consent in the command.
A positive preview can expire immediately, is advisory, and MUST NOT be used
as a real send authorization.

Every result has only fixed status/reason enums; never log raw player text,
tokens, DB URLs, Discord IDs or SQL error details.

## CI acceptance

- Unit coverage verifies restrictive command arguments, forbidden old
  world/routes, exact DEV database identity, network-disabled environment,
  read-only-first SQL ordering and sanitized failures.
- The existing rollback-only PostgreSQL 17 Sentinel test verifies the
  real database reader against one original SDK-shaped synthetic event:
  positive before response, blocked on wrong route, and blocked when the
  fake ACK/outbox already exists.
- All operations in CI are confined to disposable
  `living_world_ci` and synthetic worlds; fixture state rolls back.

## Remaining before the first real visible reply

1. A separate safe, explicit owner approval to create a **new** DEV
   world/private parent/thread, player mapping, local presence and host
   speech policy. Do not reuse/rearm the consumed Sentinel source.
2. Persistent operator authentication and a database-backed, event-unique,
   one-shot approval/claim with hard fail-closed attempt semantics.
   M2.15K's in-memory latch is **not** this mechanism.
3. An owner-approved new live Gateway inbound after all policy checks.
4. A separately reviewed action-time production provider/outbound gate
   rechecking source/route/host permission and the durable attempt **at
   the actual HTTP side effect**. No automatic retries after uncertainty.
5. Explicit owner approval for precisely one fixed-text Discord send
   in the original private test thread, followed by audit/stop and
   visual verification. Paid LLM inference is **later**.

This PR must remain Draft until final CI/security/static review and a
separate owner squash-merge decision. No deployment, DEV DB changes,
live SDK connection, webhook send or paid inference are authorized here.
