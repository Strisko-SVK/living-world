# M2.15F — Migration 0018 operator preflight and private backup handoff

**Status: Draft; no DEV database migration approved or performed.**
This is a future operator runbook, not permission to execute its write step.

## Goal

After the merged M2.15E PR #41, migration
`0018_scene_speech_policies` exists in source code on `main`. It must
eventually be applied to the owner's **persistent, isolated local**
`living_world_gateway_dev` PostgreSQL 17 database. Unlike disposable CI,
the DEV volume contains the already-consumed Sentinel inbound and must be
preserved.

The existing `gateway-dev-db.ts migrate` calls Drizzle's generic migrator.
It is **not** a preview command. Run it only after a separate, explicit
owner approval for migration 0018 on this exact isolated database.

## 1. Inspect the local destination (read only)

From a clean checkout of the reviewed main, with existing private
`.env.gateway-dev.local`, Node.js 22 and Docker Desktop/Engine:

```bash
git status --short
git rev-parse --short HEAD
docker context show
docker context inspect
docker compose --env-file .env.gateway-dev.local -f compose.gateway-dev.yml config --quiet
docker compose --env-file .env.gateway-dev.local -f compose.gateway-dev.yml ps
node --env-file=.env.gateway-dev.local --import tsx src/admin/gateway-dev-db.ts check
```

Inspect the Docker context **on the machine**: it must be the owner's own
local engine, never a remote Docker daemon, SSH context, forwarded socket
or production VPS. The container must publish only
`127.0.0.1:55432->5432/tcp`. A loopback URL **does not** independently
prove the Docker daemon is local. Never paste environment files, a raw
`docker inspect` or an unredacted `docker compose config` into chat.
If the working tree is dirty or the context/port/DB identity differs,
stop without migrations or volume operations.

## 2. Preflight — safe read-only command

This command is available **after M2.15F is reviewed and merged**, not in
the current M2.15E source code:

```bash
node --env-file=.env.gateway-dev.local --import tsx src/admin/scene-policy-migration-preflight.ts --preview
```

This command opens only the pinned localhost DEV endpoint, then sets the
PostgreSQL transaction **READ ONLY before any queries**. It verifies the
actual database/role/owner, PostgreSQL version, non-privileged DEV role,
the **complete local 0000–0018 journal and approved 0018 SQL blob**,
the applied Drizzle migration timestamps, route-revision trigger and 0018
schema status. If source code has another pending migration (for example 0019) or 0018 SQL has changed, it fails _before opening a connection_. It never calls Drizzle's migrator,
generates NPC text, writes rows or connects to Discord.

A fixed-category, shareable JSON is returned:

- `ready_for_backup` / `pending_exactly_0018`: precisely the original
  0000–0017 history is applied and the 0018 table/triggers do not exist.
  **This is not authorization to migrate.**
- `already_applied` / `already_applied_verified`: all 0000–0018 journal
  entries are present, and the table/required triggers/indexes/constraints
  exist. **Do not rerun migration.**
- `blocked`: wrong identity/environment, journal drift, absent route
  trigger, partial schema or read failure. Investigate privately, do not
  fix by resetting, recreating or deleting a volume.

Share only the JSON, not the DB URL, raw SQL, backup or secrets.

## 3. Private backup — required immediately BEFORE the approved migration

These are future commands **to be run only as part of a separately
approved local migration operation**. Do not run them now. Stop on any
error. The backup must be outside the Git repository and never uploaded
to GitHub, Notion or chat. With the verified local Docker context:

```bash
umask 077
BACKUP_DIR="$HOME/.living-world-private-backups"
mkdir -p "$BACKUP_DIR"
chmod 700 "$BACKUP_DIR"
BACKUP_PATH="$BACKUP_DIR/gateway-dev-before-0018-$(date -u +%Y%m%dT%H%M%SZ).dump"
docker compose --env-file .env.gateway-dev.local -f compose.gateway-dev.yml exec -T postgres pg_dump -U postgres -d living_world_gateway_dev -Fc > "$BACKUP_PATH" &&
test -s "$BACKUP_PATH" &&
docker compose --env-file .env.gateway-dev.local -f compose.gateway-dev.yml exec -T postgres pg_restore --list < "$BACKUP_PATH" > /dev/null &&
echo "Local backup created and TOC readable. Keep the file private."
```

`pg_restore --list` checks the dump directory; it does not prove that
a full restore would succeed. Keep the private backup even after a
successful migration until recovery has been independently reviewed.

## 4. Migration execution — **separate owner approval required**

Only after the owner explicitly approves applying migration 0018,
preflight returned `ready_for_backup`, the backup succeeded, the
reviewed checkout and Docker context are unchanged, and there are
**no other pending migrations**, the existing migration runner can be
invoked on the local host:

```bash
node --env-file=.env.gateway-dev.local --import tsx src/admin/gateway-dev-db.ts migrate
```

It performs database writes. Never run it as part of a preview, CI on
the owner's machine, or on an unverified/remote Docker host.

## 5. Read-only postcheck

After the separately approved execution, run the same
`scene-policy-migration-preflight.ts --preview` command. It must report
`already_applied` / `already_applied_verified`; other results are
blockers, not invitations to retry the migrator.

No policy rows, NPC responses, Discord sends or LLM requests are created
by migration 0018. If validation fails, **preserve the database volume
and backup**. Do not blindly re-run the migration, truncate tables, run
`down --volumes`, or attempt a production restore. Recovery requires an
independent plan and owner authorization.

## What this does NOT unlock

Even a successful migration does **not** authenticate Discord DMs,
approve NPC activity/perception facts, authorize generation or send a
reply to the historical Sentinel source message. The existing
`lw-dev-npc-e2e-001` event remains consumed; only a later, freshly
authorized event could be used for an eventually approved live test.
The owner must separately approve any live outbound/paid LLM/deployment.
