# M2.15E — PostgreSQL-backed host scene-speech evidence

**Status:** Stacked Draft PR on top of unmerged M2.15D PR #40; **no merge
or application of migration 0018 to the owner's DEV database approved**.

## Why a host-only bridge first?

The owner-local Sentinel M2.15C preview proved the authenticated original
message and NPC's pre-existing presence in the scene. It cannot establish
that Sentinel is free, listening or clear of a competing scene.

Our current database has no authenticated, **world-scoped DM membership**
model. An arbitrary Discord role, displayed name, player message or
caller-supplied `issuedByRole` cannot be promoted into authority.

This slice therefore adds **host operator / isolated CI only** evidence.
Its issuer is authenticated by the dedicated local database role and access
to the offline host, not by an asserted DM entity ID. The stored
`issuerEntityId` is attribution metadata, not proof that this person
has DM privileges. Real DM membership, authorization and UX remain future
work.

## Implementation

- `npc_scene_speech_policies` stores world, NPC, scene, exact pre-existing
  local-presence grant, NPC state version, issuer attribution, decision
  (`allow_direct_speech|hold|deny`), structured activity,
  awareness, concurrent-scene evidence, issue/expiry and revocation.
- Migration `0018_scene_speech_policies.sql` creates the empty table,
  composite world/presence/issuer FKs, one-open-policy unique index,
  30-minute maximum validity and an immutable-evidence trigger. Before
  insert, PostgreSQL resets the issue time and issuer role to the
  authenticated current DB principal and caps expiry. The trigger rejects
  inserts and revocations outside `living_world_ci` /
  `living_world_gateway_dev` with their dedicated DB users.
- Repository `scene-speech-policies.repository.ts` validates the
  **same-world** NPC, scene, route policy, issuer metadata, state version,
  location and non-revoked local presence in short transactions, under the
  existing local-context lock order. It can issue, read and revoke a host
  policy; a revoked or stale record is never returned as trusted evidence.
- Synthetic PostgreSQL 17 fixture exercises host issuance, duplicate
  refusal, matching-scope read, immutable source event, safe revocation,
  missing evidence after revoke and unchanged existing read-only preview.
- The already-merged M2.15C read-only preview is **not** modified. Nothing
  in the normal runtime, HTTP handlers, Gateway, LLM, operator CLI or
  outbound adapter imports this new repository.

The pure M2.15D advisory policy continues to return
`canGenerate=false`, `canSend=false`, `canGrantPresence=false`,
even after the trusted repository finds a candidate for a *fake* rehearsal.

## Non-negotiable boundaries

This schema migration is **code only** until separately approved for the
owner's DEV DB. CI applies it solely to disposable isolated PostgreSQL 17
databases. No production migration, deployment, live Discord message,
model call, new Gateway connection, DEV fixture reset or replay is allowed.

The consumed Sentinel message cannot be retroactively authorized by a
policy created after the event. A **fresh** source event following a valid
policy must be used for any future test. No host command to issue policy
is enabled by this PR; new features require a trusted operator
composition root and an independent authorization review.

## Limitations / follow-up

- World-scoped DM membership/authentication remains unimplemented. Only
  the isolated local host principal is supported; `world_dm` evidence
  must be rejected until a real audited membership model exists.
- The policy is **not** an assertion that NPC free/aware/occupancy facts
  were observed from a trustworthy, independent simulator; the local host
  explicitly attests those facts during a bounded first-contact setup.
- The final LLM/dispatch action boundary must re-evaluate current
  world, scene, mapped player, original source event, authorized route,
  NPC state version, revocation and expiry in a single consistent
  transaction before any real generation or delivery.
- M2.15D's fake coordinator is still test-only; this PR adds a real
  PostgreSQL record repository but not a complete new automated
  end-to-end NPC conversation.

## Review and release gates

1. Full CI on the **exact PR head**: TypeScript, ESLint, Prettier,
   Vitest, PostgreSQL 17 and isolated Gateway DEV, security scans.
2. Independent review of manual Drizzle snapshot and journal consistency.
   The snapshot is derived from the latest existing snapshot (0016);
   migration 0017 is trigger-only and has no separate schema snapshot.
3. Only after separate approval of #40 and a verified green stacked PR
   should we consider a merge, followed by **separate explicit approval**
   for applying migration 0018 to the owner's DEV DB.
4. Never rerun the old Sentinel one-shot or use its source message as
   evidence for new speech permission.
